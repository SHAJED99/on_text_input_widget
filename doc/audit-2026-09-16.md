## 2. Documentation corrections applied

Two claims written into `CLAUDE.md` were wrong and were corrected in place.

**2.1 Wrong parameter name.** The controller parameter was documented as
`controller`; the actual name is `textEditingController`
(`lib/src/on_text_input_widget.dart:353`).

**2.2 Wrong `errorCheck` semantics.** Documented as firing "on every validation
run regardless of mode". It does not. The validator returns early when the
message is null (`lib/src/on_text_input_widget.dart:592`), so `errorCheck` fires
only on validation *failure*, plus a `(false, '')` call when tapping the field
clears an existing error (`:580`). It never fires on successful validation.

`errorBuilder` was also described as a standalone third rendering mode; it is
not (see 4.1).

**2.3 Same error existed upstream.** `README.md:138` and `AGENTS.md` both
documented `errorCheck` as firing whenever validation runs. Both corrected, along
with the `AGENTS.md` claim that `errorBuilder` works independently of
`showDetailError` (it does not — see 4.1).

## 3. Claims verified as correct

- `part` / `part of` single-library structure; all imports confined to
  `lib/on_text_input_widget.dart`.
- Controller ownership is consistent across all three lifecycle sites:
  `initState` (`:334`), `didUpdateWidget` (`:355-363`), `dispose` (`:376`).
  Internally created controllers are disposed; caller-supplied ones are not.
- Debounce pipeline drains `searchProductList.last` behind the `isIdle` guard,
  with a deliberate `try/catch` around the `await` so a throwing callback still
  resets `isIdle` (`:547-558`).
- UserField shows the eye suffix only when `_string` is non-empty
  (`widgets/user_field.dart:146`) and re-obscures on focus loss (`:195`).
- Default height falls back to the deprecated `theme.buttonTheme.height`
  (`:475`), matching the intent recorded in commit `f8af1a9`.
- Lint set in `analysis_options.yaml` is as documented.

## 4. Bugs found

> Both were fixed in 0.2.0. Recorded here as found; see section 8.

### 4.1 `errorBuilder` without `showDetailError` silently swallows the error

`errorChild()` guards on `error && widget.showDetailError && message != null`
(`lib/src/on_text_input_widget.dart:430`) and otherwise returns `SizedBox()`.
But the validator already skips the clear-input / hint-text fallback whenever
`errorBuilder != null` (`:596`).

Consequence: setting `errorBuilder` *without* `showDetailError` disables the
default error presentation and never reaches the custom builder — the error is
displayed nowhere. Either the guard should drop `showDetailError` when a builder
is supplied, or the validator should not treat `errorBuilder` as opting out of
the fallback.

Not covered by tests: the `showDetailError` test always sets the flag.

### 4.2 `validator` always returns `null`, so `Form.validate()` always succeeds

The validator returns `null` on every path, including after setting
`error = true` (`lib/src/on_text_input_widget.dart:584-603`). An enclosing
`Form` therefore always validates successfully and these fields can never block
a submit. Given `OnTextInputWidgetUserField` is aimed at login forms, this is
likely unintended.

Fixing it is a behavior change that could break consumers relying on submit
always succeeding — warrants a CHANGELOG "Breaking" note.

Not covered by tests: no test wraps the widget in a `Form`.

## 5. Parameter naming recommendations

> Applied in full in 0.2.0, as a clean break without `@Deprecated` shims.

Rationale: `OnTextInputWidget` and `OnTextInputWidgetUserField` are both public
and disagree with each other on names for the same concepts, and
`user_field.dart:190-191` maps one spelling onto the other. At `0.1.0` a clean
break is cheaper than `@Deprecated` shims.

| Current | Proposed | Where | Why |
|---|---|---|---|
| `maxLine` / `minLine` | `maxLines` / `minLines` | UserField `:27-28` | Main widget and Flutter both use the plural |
| `enable` | `enabled` | UserField `:29` | Main widget and `TextField.enabled` |
| `textEditingController` | `controller` | both widgets | Flutter-wide convention |
| `errorCheck` | `onError` | main `:32` | Every other callback uses the `on*` prefix |
| `onChangeDebounce` | `debounceDuration` | main `:30` | Not a callback; reads like one. Optional |

Deliberately left alone: `svg` / `prefixChild` on UserField (genuinely different
from `prefix` / `prefixIcon`), and `border` (odd but a doc comment fixes it).

Blast radius for the renames: 4 call sites in `test/`, 3 rows in `README.md`,
none in `example/lib`.

## 6. Version constraints (corrected)

The declared `environment` block was wrong in two independent ways.

**6.1 The declared pair was unsatisfiable.** `sdk: '>=3.0.0 <4.0.0'` with
`flutter: '>=3.3.0'`: Flutter 3.3 ships Dart 2.18, and Dart 3.0 first shipped in
Flutter 3.10. No Flutter in [3.3, 3.10) could satisfy both.

**6.2 The dependency floor is far higher.** `flutter_svg: ^2.0.10+1` resolves to
2.2.0, which declares `sdk: ^3.6.0` / `flutter: >=3.27.0`, and `pubspec.lock`
pins exactly that. The configuration actually built and tested is Flutter 3.27.4
/ Dart 3.6.2 — nine minor versions above what was advertised. A consumer on an
older Flutter would have pub backsolve to an untested `flutter_svg` 2.0.x, where
the `colorFilter` API used in `svg.dart:15` has shifted within the 2.x line.

Corrected to `sdk: '>=3.6.0 <4.0.0'` / `flutter: '>=3.27.0'`, matching the
lockfile and the FVM pin. The alternative — genuinely supporting older Flutter by
pinning `flutter_svg: '>=2.0.10 <2.1.0'` and adding multi-SDK CI — was not taken.

Unverified: `AGENTS.md` previously claimed `onTapOutside` requires Flutter 3.3+;
it is believed to be 3.7+ (it arrived with `TapRegion`). Moot at a 3.27 floor, so
the per-API notes were dropped rather than corrected.

## 7. Other observations

- `fvm dart analyze lib/` (the command `AGENTS.md` prescribed) reports 0 issues,
  but whole-package `fvm dart analyze` reports **25**, all in
  `test/on_text_input_widget_test.dart` (`always_specify_types`,
  `lines_longer_than_80_chars`). All `info` severity. The documented command was
  changed to plain `fvm dart analyze`.
- `dart pub publish --dry-run`: 2 warnings — 9 modified generated files under
  `example/` (left untouched, per the contributor note about not committing SDK
  churn), and a pub-layout warning that led to this file living in `doc/` rather
  than `docs/`.
- `flutter_lints: ^2.0.0` is several majors behind current (5.x/6.x). Not an
  error; noted only.
- The documented `fvm flutter test example/` **fails to compile**: run from the
  repository root it cannot resolve `package:example`, so `widget_test.dart`
  fails on `import 'package:example/main.dart'`. Pre-existing, unrelated to any
  change in this audit. The command must be run from inside `example/`, and
  `AGENTS.md` was corrected accordingly. The test itself passes.
- `example/pubspec.yaml` declared `sdk: ^3.3.1` while consuming a package whose
  floor is now 3.6.0; aligned to `^3.6.0` / Flutter `>=3.27.0`.
- UI / accessibility findings were reviewed separately and deliberately **not**
  acted on: destructive input-clearing on validation error, no `Semantics` or
  `Tooltip` anywhere in `lib/`, sub-48dp touch targets (24×24 password toggle,
  36dp default field height), `errorStyle: fontSize 0` suppressing native error
  semantics, and colour as the sole error signal. Recorded here for future work.

**Still open — the sole exception:** the default field height remains

deliberate. Commit `f8af1a9` chose it so fields align with

alignment for every existing consumer. Documented with the
`boxConstraints: BoxConstraints(minHeight: 48)` override instead. Revisit only
as an explicit design decision — an opt-in flag would preserve both.
